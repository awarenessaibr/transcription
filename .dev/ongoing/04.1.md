## Field semantics (agent-facing contract)

| Report | Question it answers | Passes when |
|---|---|---|
| **coverage** | Is every local ELI in Qdrant, and every Qdrant point backed by a local file? | `missing_total == 0` AND `extra_total == 0` |
| **identity** | When two local files claim the same ELI, is that legitimate (multi-locale) and is a canonical source declared? | `unintentional_duplicate == 0` AND every collision has non-null `canonical_source` |
| **provenance** | Does each Qdrant point record which local file it came from, matching the canonical source? | `mismatched == 0` AND `missing_source_field == 0` |
| **fidelity** | Does the ingested text byte-match (or normalize-match) the canonical local text? | `drift == 0` AND `unreadable == 0` |

The top-level `gates.overall == "pass"` is the single boolean a CI job should gate on. Any of the four being `fail` forces `overall: fail`.

`reference_only` files are excluded from coverage's missing/extra counts; their `blocks_without_eli` are reported for transparency only.

# Part B — Agent instructions: full clean ingestion, once

These are the operating instructions for the ingestion agent. Follow them literally. Do not shortcut phases. Do not publish a "pass" gate without producing the four sub-reports.

## 0. Mission

Bring `data/law/` (119 `.md` files, 1,145 unique ELIs) into **exact one-to-one correspondence** with Qdrant collection `la8159_law`, with complete provenance and zero content drift, and produce a `law_registry.json` conforming to `law_registry.v2.schema.json` where `gates.overall == "pass"`.

## 1. Preconditions

Before doing anything, verify and record:

1. `data/law/` is the only source of truth for content. Nothing in Qdrant is authoritative.
2. A backup of the current Qdrant collection exists (`la8159_law_backup_<UTC>`), and a restore command has been tested.
3. You can read every `.md` file's raw bytes and compute SHA-256.
4. You can write the following artifacts atomically:
   - `data/law/.manifest/canonical.json`
   - `data/law/.manifest/ingest_log.jsonl`
   - `law_registry.json` (v2 schema)
5. `data/law/schemas/law_registry.v2.schema.json` is present.

If any precondition fails, **abort** and report. Do not proceed with a partial corpus.

## 2. Phase A — Freeze and canonicalise

Do this on a working copy or in a branch. Do not mutate `data/law/` until Phase C.

### A.1 Canonical source per ELI

Produce `canonical.json`: a map from `eli → { source_path, sha256, language }`.

Resolution rules, applied in order:

1. If an ELI appears in exactly one file, that file is canonical.
2. If an ELI appears in multiple files with the same language, **this is an error**. Stop and report the collision. Do not guess.
3. If an ELI appears in multiple files with different languages, it is an `intentional_multilocale` collision. Choose canonical by this precedence: `es > en > pt`. Record the losing files in `alternates[]` — do not delete them.
4. `source_path` is the **relative path from the repo root** (e.g. `CL/CodigoPenal.md`), never a basename.

Every collision must be recorded in the identity report. No silent choices.

### A.2 `doc_type` mapping

Recompute the derived `doc_type` for every ELI using the current mapping function. Before ingestion, run a dry-run that emits the drift list. If `doc_type_drift > 0`, fix the mapping function **first** — do not ingest with a known-broken derivation.

### A.3 Content fingerprints

For every canonical `(eli, source_path)`, compute:

- `raw_sha256` — SHA-256 of the raw bytes of the article block.
- `norm_sha256` — SHA-256 after: NFC normalisation, whitespace collapse, removal of line-ending differences, removal of BCN amendment-marker blockquotes prefixed with `> **BCN amendment note:**`.

Both hashes go into `canonical.json`. Both are what fidelity checks against.

## 3. Phase B — Dry run

Do **not** touch Qdrant in this phase. Emit:

1. A `dry_run_registry.json` (same v2 schema, real numbers, `gates` computed honestly).
2. A `plan.jsonl` with one line per ELI:

```json
{"eli":"...","action":"insert|replace|skip|delete","source_path":"...","raw_sha256":"..."}
```

Expected plan outcomes on the first run:

- `insert` for every ELI in `canonical.json` not present in Qdrant (currently 26–29).
- `replace` for every ELI whose Qdrant `raw_sha256` differs from local (currently 52).
- `skip` for every ELI that is present and byte-identical.
- `delete` for any Qdrant point with no local source (currently 0).

Review the plan against the current known state. Stop if any unexpected `insert` or `delete` appears — that means `canonical.json` is wrong.

## 4. Phase C — Ingest

1. Write the full `canonical.json` and `plan.jsonl` hashes to `ingest_log.jsonl` before making any Qdrant mutation.
2. Apply the plan in deterministic order: `delete` → `replace` → `insert`. Never `insert` before `delete` on the same ELI.
3. Every Qdrant point must carry these payload fields:

   ```
   eli                 (string, required)
   source_path         (string, required — relative path, not basename)
   language            (string, required — "pt" | "es" | "en")
   raw_sha256          (string, required)
   norm_sha256         (string, required)
   doc_type            (string, required)
   title               (string, required)
   theme               (string, required)
   tags                (array<string>, required)
   ```

   If any of these is missing, the point is invalid — treat it as an ingestion failure, not a data-quality warning.

4. After every 100 mutations, append a checkpoint line to `ingest_log.jsonl`. If the process dies, the log is the resume point.

## 5. Phase D — Verify

Regenerate `law_registry.json` conforming to `law_registry.v2.schema.json`. This is the **only** output a reviewer will look at.

Acceptance gates — all four must pass:

| Gate | Condition |
|---|---|
| coverage | `missing_total == 0` AND `extra_total == 0` |
| identity | `unintentional_duplicate == 0` AND every collision has `canonical_source != null` |
| provenance | `mismatched == 0` AND `missing_source_field == 0` |
| fidelity | `drift == 0` AND `unreadable == 0` |

If any gate fails, **do not announce success**. Report the failing sub-report verbatim, plus a diff of the expected vs actual state for each violating ELI.

Additionally, before declaring done:

- Re-run the generator twice; the two outputs (excluding `generated_at`) must be byte-identical. This proves determinism.
- Manually spot-check **five random** ELIs: pull the local article text and the Qdrant text and diff them character-by-character. Any mismatch = fidelity gate is lying; fix the generator.

## 6. Phase E — Cutover

Only after `gates.overall == "pass"`:

1. Atomically swap Qdrant collection `la8159_law` with the newly built one (or keep both and flip the alias used by clients). Do not leave both live without an alias flip — clients will read the wrong one.
2. Commit `law_registry.json`, `canonical.json`, and `ingest_log.jsonl` to the repo.
3. Tag the commit `law-ingest-<UTC>`.
4. Update `LAW_REGISTRY.md` to be generated from the v2 report (drop the old single-table format).

## 7. Rollback

If verification fails and cannot be fixed inside a single session:

- Do **not** touch the live Qdrant collection.
- Leave the dry-run artifacts in place.
- Open an issue titled `law-ingest blocked: <failing gate>` with the failing sub-report attached.
- Restore from the backup only if Phase C already ran on the live collection.

## 8. Anti-patterns — do not repeat these

These are the specific mistakes the current corpus exhibits. The agent must not reproduce them:

1. **Do not treat "the ELI appears in another local file" as evidence it exists in Qdrant.** Presence in Qdrant is verified only by reading Qdrant.
2. **Do not write `source_basename`.** Write `source_path` (relative path). Basenames collide across `CL/`, `BR/`, `INT/`.
3. **Do not publish a `genuinely_missing` count without cross-checking every `alias_eli`.** An ELI declared as alias but absent from every `in_qdrant_eli` is missing, not aliased.
4. **Do not ingest PT/EN treaty pairs twice under the same ELI.** Pick one canonical (per A.1 rule 3), record the other as an alternate.
5. **Do not ingest a file that has been edited but not re-hashed.** Fidelity is byte-level, not eyeball-level.
6. **Do not announce a pass without a `validation_ok` boolean derived from the four sub-reports.** A bare `validation_ok` without the sub-reports is unactionable.
7. **Do not skip the dry run.** Every previous state of this corpus that ended in a `validation_ok: false` did so because the plan was not reviewed before mutation.

## 9. Definition of done

The task is complete when **all** of the following are true:

- `law_registry.json` validates against `law_registry.v2.schema.json`.
- `gates.overall == "pass"`.
- Two consecutive generator runs produce identical output apart from `generated_at`.
- Five random ELIs pass a manual character-level diff.
- The commit is tagged and `LAW_REGISTRY.md` is regenerated from the v2 report.
- The live Qdrant alias points at the verified collection.

If any of those is not true, the task is not done. Report where it stopped.
