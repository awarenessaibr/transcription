# Law Corpus Cleanup — duplicate and non-ELI articles removed

**Scope.** Turn request: *"remove any article law which is duplicate, or has wrong or no
eli ID, so we can have the law articles as intended."* Applied against the local
`data/law/**/*.md` corpus only; the shared Qdrant collection `la8159_law` was **not**
touched (explicit user choice: *"Corpus only — do not touch Qdrant"*).

**Verdict in one line.** Seven files changed (2 trimmed, 5 deleted); the corpus now holds
**1145 articles, 1145 unique ELIs, 281 intentional multilocale collisions and 0
unintentional duplicates**, and **every remaining block in the corpus carries an ELI ID**
(`blocks_without_eli: 0`, down from 194).

## 2. Root cause — the corpus was mid-migration

| Commit | Date | Content |
|---|---|---|
| `6cf8fb8` | 2026-09-18 | old multi-article **excerpt** files |
| `c3a4ee0` | 2026-09-19 | one file **per article** + its BCN source PDF |

`c3a4ee0` added the per-article files but **deleted nothing**, so the blocks it superseded
survived inside the older excerpts as duplicates. Rule adopted: **the per-article file
wins** — it is newer, has its own source PDF, and is strictly more complete.

Verified case: the `Art. 228` in `CodigoPenal_Prevaricacion.md` carried only **one inciso**;
`CL/CL.CPCL.C1.Art.228.md` carries **two**. The excerpt was truncated, so removing it loses
nothing. (It did *not* have fewer BCN amendment notes — both copies have the same two. Only
`CL.CPCL.C1.Art.269_ter` showed a note deficit.)

One collision was actively harmful: `CL.CPCL.C1.Art.269_ter` was the live Qdrant point for
`CL/CodigoPenal.md` — the **degraded** copy (578 chars, **0 BCN notes**, empty `theme`,
accents stripped, no `**Source:**` link) — while the richer copies (780 chars / 2 notes and
844 chars / 3 notes) lost the collision. That is the quality bug the cleanup fixes.

## 3. New finding — a translation filed in the wrong language tree

`INT/EN/BR_CL_Joint_Declaration_2024.md` was **byte-identical** to
`INT/BR/BR_CL_Joint_Declaration_2024.md`: Portuguese text sitting in the English tree, while
declaring `INT.BRCL.JOINTDECL.2024.Item.*`.

`LawCorpusParser._pick_variant` uses `_DEFAULT_PREFERRED_LANGUAGE = "en"`, so it selected the
**English** copy and ingested Portuguese into the English slot — and because both trees
carried the same 8 ELIs, the corpus claimed 8 phantom `pt`/`en` pairs. This is the sole
reason `en` moved **292 → 284** and `pt` moved **674 → 682** after deletion. It is *not* a
counted collision, which is why earlier inventory passes missed it.

`BR.ABEAR_PMD.Art.10` / `BR.ABEAR_PVR.XI`: identical *boilerplate* in **distinct articles of
distinct ANAC acts**. They are not removable.

## 7. The three gates that still fail — all already-decided or structural

1. **provenance (`missing_source_field 1119`).** The canonical `to_payload()` writes no
   `source_path`; only `local_payload()` does. Per `05.md` §6.3 option 2, the fix belongs to
   the repo-owned `transcription_law` collection. **The gate must not be relaxed to accept
   `source_file`** — 21 of 98 basenames are ambiguous (`INT/BR/*` vs `INT/EN/*` pairs).
2. **coverage (`missing_total 26`, all `CL.*`).** Articles live in Qdrant that no longer
   exist locally — a consequence of the clobbered `data/law/_mapping/law_registry.json`.
   Touching the shared collection is out of scope by the user's choice.
3. **fidelity (`drift 52`).** Known items: the derived `INT.AN9.C6.S45.Art.6.45` mapping, the
   stray `Legal`-token anomaly, and 5 articles where `_METADATA_LINE_RE` leaks a metadata
   line into the body.

`reference_only_blocks` reaching 0 means the coverage gate's remaining failure is purely the
26 upstream-missing ELIs — the corpus side is now clean.
